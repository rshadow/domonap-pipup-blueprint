# Domonap → PiPup: видео звонка на телевизоре

Чертёж Home Assistant показывает видео домофона в небольшом окне поверх
приложений Android TV. Пока видео подключается, видна фотография звонка.
После завершения звонка окно скрывается с настраиваемой задержкой.

**Рабочий черновик.** Проверен на Home Assistant 2026.11.0, PiPup для HA 1.31.0
и приложении PiPup 0.31.0 на Android 14. Ручная проверка переключением датчика
и проверка после перезапуска HA прошли. Настоящий звонок и перезагрузка самой
приставки отдельно ещё не проверены.

Установка идёт по порядку: приложение на ТВ → интеграция PiPup в HA →
интеграция Domonap и проверка камеры → этот чертёж.

## 1. Установить PiPup на телевизор или приставку

1. Скачайте APK из [релизов форка mhoogenbosch/PiPup](https://github.com/mhoogenbosch/PiPup/releases).
   Нужен именно этот форк с поддержкой WHEP; в проверке использовалась версия 0.31.0.
2. Установите APK на Android TV или приставку, где должно появляться окно.
3. Откройте PiPup и разрешите показ поверх других приложений. На некоторых
   устройствах разрешение выдаётся через ADB — см. [инструкцию установки автора](https://github.com/mhoogenbosch/PiPup#installation-sideloading).
4. Если система ограничивает фоновую работу, разрешите её для PiPup.
   На экране приложения проверьте состояние службы и запомните IP-адрес устройства.

HA должен обращаться к приставке по сети, а приставка — открывать ссылки
на видео и фото из HA. Порт API PiPup по умолчанию — `7979`.

## 2. Добавить интеграцию PiPup в Home Assistant

1. Откройте **HACS → меню ⋮ → Пользовательские репозитории**.
2. Добавьте [mhoogenbosch/ha-pipup](https://github.com/mhoogenbosch/ha-pipup)
   с типом **Integration / Интеграция**.
3. Установите **PiPup** и перезапустите Home Assistant.
4. Откройте **Настройки → Устройства и службы**. Настройте обнаруженную
   приставку либо нажмите **Добавить интеграцию → PiPup**, укажите её IP-адрес
   и порт `7979`. Имя устройства можно выбрать самостоятельно.
5. В **Инструменты разработчика → Действия** вызовите `pipup.show`:
   выберите приставку, задайте заголовок «Проверка PiPup» и время показа 5 секунд.
   Убедитесь, что окно появилось поверх приложения на ТВ.

Если HACS не установлен, у автора есть [способ ручной установки](https://github.com/mhoogenbosch/ha-pipup#installation).
Отдельная REST-команда для этого чертежа не нужна.

## 3. Добавить Domonap и проверить камеру

1. В пользовательских репозиториях HACS добавьте
   [svmironov/domonap_intercom](https://github.com/svmironov/domonap_intercom)
   с типом **Integration / Интеграция**.
2. Установите **Domonap** и перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Domonap**
   и выполните авторизацию. Для профиля **Rubetek Panel** нужен код активации
   от поддержки Domonap; подробности — в [инструкции профиля](https://github.com/svmironov/domonap_intercom/blob/main/docs/rubetek-panel.md).

### Найти и проверить живое видео

До установки чертежа откройте нужную дверь на странице устройств Domonap
и найдите её сущность **камеры** (`camera.…`). Запустите просмотр в HA и
убедитесь, что изображение меняется: это должно быть живое видео, а не
сущность **«Фото звонка»** (`image.…`). Проверьте каждую дверь, которую хотите видеть на ТВ.

Затем в **Инструменты разработчика → Состояния** выберите камеру и проверьте
наличие непустого атрибута `go2rtc_webrtc_url`. Чертёж использует именно эту
ссылку для WebRTC-видео. У того же устройства должен быть бинарный датчик
**«Входящий звонок»**; «Фото звонка» нужно только для заставки.

Если камера не показывает видео в HA или атрибута `go2rtc_webrtc_url` нет,
сначала настройте камеру в интеграции Domonap. Чертёж не создаёт видеопоток.

## 4. Импортировать чертёж и создать автоматизацию

[![Импортировать чертёж в Home Assistant](https://my.home-assistant.io/badges/blueprint_import.svg)](https://my.home-assistant.io/redirect/blueprint_import/?blueprint_url=https%3A%2F%2Fgithub.com%2Frshadow%2Fdomonap-pipup-blueprint%2Fblob%2Fmain%2Fblueprints%2Fautomation%2Fdomonap_pipup_calls.yaml)

1. Откройте [файл чертежа](blueprints/automation/domonap_pipup_calls.yaml)
   на GitHub и скопируйте адрес его страницы.
2. В HA откройте **Настройки → Автоматизации и сцены → Чертежи → Импортировать чертёж**,
   вставьте адрес и подтвердите импорт.
3. Найдите **«Domonap: видео звонка на ТВ через PiPup»** и нажмите **Создать автоматизацию**.
4. Выберите аккаунт Domonap и одну или несколько приставок PiPup.
   При необходимости выберите двери, которые нужно исключить.
5. Проверьте параметры ниже и сохраните автоматизацию. Если раньше уже была
   автоматизация показа тех же звонков, отключите её, чтобы окна не дублировались.

| Параметр | По умолчанию |
|---|---|
| Положение | Справа внизу |
| Размер видео | 640×480 |
| Звук камеры | Включён |
| Фото до первого кадра видео | Включено |
| Режим фото перед видео | Не переопределять |
| Включать устройство перед показом камеры | Отключено |
| Время ожидания включения | 15 секунд |
| Анимация | Отключена |
| Максимальное время показа | 180 секунд |
| Задержка скрытия после окончания звонка | 5 секунд |

Поле **«Адрес HA для фотографий»** обычно оставляют пустым: адрес определяется
из ссылки камеры. Заполните его, если для доступа с приставки требуется другой
адрес HA. Все настройки экземпляра сохраняются отдельно от файла чертежа.

### Режим фото перед видео

Если пропорции фото отличаются от видео, выберите **«Режим фото перед видео»**.
Явный режим удерживает фото внутри заданных размеров видео и не даёт ему менять
размер окна. Нужны приложение PiPup **0.32.0-beta.4** и HA-интеграция
**1.32.0b4** или новее; в этих версиях поддержка пока предварительная.

| Режим | Как показывается фото |
|---|---|
| Не переопределять | Параметр не передаётся; прежнее поведение сохраняется, поддерживаются старые версии PiPup |
| Вписать целиком (`fit`) | Всё фото с сохранением пропорций; по краям могут остаться полосы |
| Заполнить с обрезкой (`fill`) | Заполнение области с сохранением пропорций и обрезкой по центру |
| Растянуть (`stretch`) | Заполнение всей области с изменением пропорций фото |
| По центру (`center`) | Исходный размер фото, центрирование и обрезка выходящих за область частей |

Для широкого видео 16:9 и фото 4:3 можно выбрать **«Растянуть (stretch)»**,
ширину **640** и высоту **360**. Эти значения задаются в настройках автоматизации;
размер по умолчанию остаётся 640×480. Режим влияет только на фото, масштабирование
живого видео не меняется. Если фото отсутствует или его показ выключен, заставки нет.

### Пробуждение перед показом камеры

Включите **«Включать устройство перед показом камеры»**, если хотите показывать
звонок и на спящей приставке. Чертёж сам находит `media_player` интеграции PiPup
у каждой выбранной приставки. Если экран уже включён, команда пробуждения не
отправляется. Иначе выполняется `media_player.turn_on` и ожидается подтверждённое
состояние `on` в пределах **«Время ожидания включения»**.

Если включение не подтверждено или сущность не найдена, показ на этом устройстве
пропускается с предупреждением в журнале HA; остальные приставки обрабатываются
по очереди. Если звонок закончился или сменился другим за время ожидания,
запоздавшее видео не показывается. Завершение звонка скрывает окно, но не
выключает устройство.

PiPup должен оставаться доступным по сети в режиме ожидания. Пробуждение не
включает обесточенную приставку. Включение телевизора вместе с приставкой через
HDMI-CEC зависит от оборудования и его настроек. Перед включением опции проверьте
`media_player.turn_on` на сущности PiPup своей приставки; проверка команды
`POST /power?state=on` на Ugoos с PiPup 0.31.0 прошла.

## Проверить автоматизацию вручную

В **Инструменты разработчика → Состояния** найдите датчик «Входящий звонок»
нужной двери. Меняйте только его состояние, оставляя атрибуты без изменений:

1. Установите `off`, затем `on` — должно появиться фото, а затем видео этой двери.
2. Установите `off` — через 5 секунд окно должно закрыться.
3. Для проверки повторного звонка установите `on`, затем `off`, затем снова `on`
   менее чем через 5 секунд: ожидающее скрытие должно отмениться.
4. В конце верните датчик в `off`.

Это имитация состояния в HA, она не создаёт настоящий звонок в Domonap.
Интеграция может перезаписать состояние при обновлении. Проверяйте в момент,
когда настоящего входящего звонка нет; на это состояние могут реагировать
и другие ваши автоматизации. Затем отдельно проверьте настоящий вызов.

## Поведение и ограничения

- Обрабатываются все датчики звонка выбранного аккаунта Domonap. Камера и фото
  ищутся по устройству датчика, без таблицы соответствий и зависимости от имён сущностей.
- Новые двери подхватываются после появления их сущностей в HA. Для обновления
  списка дверей может потребоваться перезагрузка интеграции Domonap.
- У каждой двери свой ID окна. Повторный звонок отменяет старый таймер скрытия.
- Если у устройства несколько камер, показ пропускается. Если фото нет или их
  несколько, окно открывается без заставки. Фото — последнее доступное в HA.
- Переходы `unknown`/`unavailable` и изменения только атрибутов игнорируются.
  Скрытие следует датчику Domonap, который также может сбрасываться собственным таймером.
- Видео запрашивается при показе окна. Постоянная предзагрузка и go2rtc не требуются.
- Без явного режима фото PiPup может подстроить высоту области WHEP под фото.
  При разных пропорциях фото и видео возможны полосы. В новых версиях выберите
  режим фото и задайте размеры под видеопоток, например 640×360 для 16:9.
- Если текстовое окно показывается, а видео или фото нет, проверьте доступность
  ссылок HA с приставки и настройки камеры. Изменение адреса для фотографий
  не исправляет недоступный адрес самого видеопотока.

Защищённые ссылки вычисляются при выполнении; токены и адреса вашего дома
не нужно добавлять в файл чертежа. Сохранение трасс этой автоматизации отключено,
чтобы ссылки не попадали в них. Не публикуйте значения `go2rtc_webrtc_url`,
токены доступа или данные сессии Domonap в обращениях за помощью.
